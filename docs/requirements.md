# 功能与权限要求

本文描述**目标要求**，不代表功能已完成。

## 1. 用户与权限

- 教师、学生登录；API 使用 JWT Bearer，并支持令牌撤销与基于角色的权限校验。
- 所有讲义、知识条目、Agent、会话、作业、成绩和报告均按服务端班级归属隔离。
- 教师只管理任教班级；学生只访问本班且属于自己的作业与错题。
- MCP 工具执行前再次校验身份、角色、班级及资源归属；越权请求可审计。

## 2. 课程基线路径

### 讲义与知识库

- 教师上传 TXT、Markdown 或文字型 PDF；服务端解析、切片、建立索引。
- 关键词与向量混合检索，采用 RRF 融合；回答附材料标题、版本与具体片段。
- 无充分证据时说明不足，不编造材料引用。
- 更新材料期间旧生效版本继续可用；新索引就绪后再切换，历史引用保持原快照。

### 智能教学 Agent

- 教师配置提示词模板、讲义范围、可用 Skill 与 MCP 工具。
- 支持多轮会话、SSE 流式回答、工具调用结果回传和异常反馈。
- Skill 至少覆盖解题引导、作业批改与错题讲解；支持启停和行为测试。
- 工具至少覆盖讲义检索、当前作业、个人错题、作业 Rubric 和班级统计。

### 作业与批改

- 教师设置题目及 Rubric，学生在允许时间内提交；批改在后台执行。
- 保存 AI 初评及其依据，教师可以复核并给出最终成绩；保留错题与错因。
- 失败任务有可见状态和重试路径，不把失败显示为已完成。

## 3. 小组新增业务

### A. 知识缺口反馈与回补

无有效讲义证据的提问形成**候选缺口**；同班相近问题归并并统计热度。教师确认或驳回，审核通过后补充材料并异步索引。只有新内容实际可检索时才标记“已补入”。保留处理记录及回补前后检索对照。

状态至少区分：待确认、已驳回、审核通过、索引中、已补入、索引失败。

### B. 同纲不同卷

教师定义题干模板、参数范围和统一评分规则；系统按学生生成不同实例及对应服务端答案。学生只能访问自己的实例；开始作答后冻结题目。单人发卷失败不影响其他学生，批改按本人的题目和答案执行。

状态至少区分：草稿、发卷中、可作答、已冻结、已提交、发卷失败。

### C. 多源学情周报

程序按班级和统计周期汇总检索、候选缺口、作业提交、错题及评分事实。模型仅基于结构化事实撰写观察与建议，不自行编造人数、比例或趋势。样本不足时明示限制。教师编辑、审核、发布后，学生才可查看本班报告。

状态至少区分：待生成、生成中、草稿、已发布、生成失败。

## 4. 非功能要求

- 数据落入真实持久化存储，核心业务通过真实 API 完成，不以静态页或 mock API 代替验收。
- 使用数据库迁移、API 文档、自动化测试、错误处理、结构化日志和调用审计。
- 容器化部署，配置健康检查、数据卷、备份及环境变量；最终验收公网 HTTPS。
