# 小组协作约定

## 分工原则

选题说明提出两位成员计划各承担约一半工作。**计划比例不是已完成贡献比例**；最终以本仓库中的 Issue、提交、PR、评审和测试证据核对。

- 方向 A：总体架构、后端基础、Agent/Skill/RAG/MCP、知识缺口与索引、发卷核心、权限及部署集成。
- 方向 B：教师/学生双端、作业与错题交互、题目模板、学情聚合、周报工作流及端到端测试。
- 共同工作：OpenSpec 与 API 契约评审、数据库设计、安全审查、联调、故障处理和最终验收。

上述分工是讨论稿。具体负责人、工作量和截止时间由成员在 Issue 中确认，不能根据此文档认定某人已完成某项实现。

## 提交约定

1. 每项需求先建 Issue，写清验收条件与负责人。
2. 对架构、数据库或接口的变更先更新规约文档并完成评审。
3. 代码和测试通过独立分支及 PR 引入；PR 关联 Issue，说明变更、测试结果与风险。
4. 不提交密钥、真实学生资料、数据库备份或私有部署配置。
5. 最终报告只引用本组真实提交和实测记录；复用外部或个人已有实现时明确来源、授权和实际改动。
