# 后端开发蓝图

本文件定义未来实现的服务边界。目标栈为 Python 3.12、Flask 3.x、SQLAlchemy 2.x、Alembic、Pydantic、LangGraph、MCP Python SDK、Redis/RQ、PostgreSQL/pgvector。版本是项目目标，不表示已安装；首个实现 PR 锁定完整依赖及镜像摘要。

## 1. 模块边界

| 模块 | 职责 | 不应承担的职责 |
| --- | --- | --- |
| `auth` | 登录、JWT 签发/刷新/撤销、当前成员关系 | 接受客户端自报角色或班级作为授权 |
| `materials` | 文件校验、正文解析、版本、下载、撤回 | 在请求线程完成大文件索引 |
| `retrieval` | 班级限定的全文/向量检索、RRF、证据评分与引用 | 把全库内容送给模型 |
| `agents` | 应用配置、提示词渲染、LangGraph 状态、SSE | 让模型输出直接成为权限决定 |
| `skills` | 技能注册、启停、输入校验、受限执行 | 直接运行未经审核的上传脚本 |
| `mcp` | 工具登记、允许列表、二次鉴权、调用与结果审计 | 让模型自由选择任意服务器/文件路径 |
| `assignments` | 模板、实例生成、冻结、提交、Rubric、批改与复核 | 把 AI 建议分覆盖为最终分 |
| `gaps` | 无证据候选、班级内归并、教师审核与回补 | 跨班归并相似问题 |
| `reports` | 确定性事实聚合、AI 草稿、教师发布 | 由模型计算人数和成绩比例 |
| `jobs`/`audit` | 任务状态、重试、结构化审计 | 在日志中保存密钥或完整敏感数据 |

Flask Blueprint 对外提供 API；业务逻辑位于服务层；数据库访问位于仓储层；Pydantic 校验输入和模型结构化输出。所有模块共用授权策略和错误响应格式。

## 2. 请求与任务流水线

1. **普通 API**：请求 ID → JWT 验证 → 当前成员关系/资源归属 → 输入校验 → 事务处理 → 审计 → 统一响应。
2. **材料上传**：格式、大小和内容校验 → 保存隔离文件 → 建立草稿版本与任务 → Worker 解析、切片、嵌入和索引 → 校验索引完整性 → 原子切换生效版本。失败保留旧版和错误状态。
3. **问答**：解析应用配置版本 → 校验用户和班级 → 在授权版本中检索必要片段 → 构造系统规则、模板、历史消息和证据 → LangGraph 决定是否调用已绑定 Skill/MCP → 二次鉴权并执行 → 关联 `tool_call_id` → SSE 输出 → 保存消息、引用和脱敏审计。
4. **作业**：教师发布模板 → Worker 按学生生成实例与服务端答案 → 冻结题目 → 学生提交 → Worker 按本人实例和 Rubric 生成 AI 初评 → 教师复核并写最终分。每个学生实例独立失败/重试。
5. **知识缺口**：证据不足 → 生成候选 → 同班相似问题归并 → 教师审核 → 补充材料索引 → 重问对照与状态更新。
6. **周报**：程序按班级/周期聚合事实 → 校验样本量 → 模型基于结构化事实生成文字草稿 → 教师编辑、审核、发布。草稿不可被学生读取。

## 3. 事务与并发约束

- 所有写入先持久化业务状态，再投递队列；队列投递失败保留可恢复状态。
- 任务需要幂等键和最大重试次数；重试不能重复发卷、重复计分或重复切换活动版本。
- 数据库连接池、请求超时、模型并发上限和队列长度限制由环境变量配置。过载优先返回可解释的限流/排队状态。
- 版本切换、最终分确认与周报发布必须在事务中检查当前状态，避免并发覆盖。
- 外部模型不可用时，非 AI 页面继续工作；AI 接口返回明确的不可用状态，不生成伪造答案。

## 4. 后端验收

pytest 覆盖服务层和 API；重点覆盖 JWT 生命周期、A/B 班与个人资源、文件校验、检索范围、工具二次鉴权、任务幂等、索引失败回退、评分历史与报告事实。真实模型集成测试与替身测试必须分别标记；未提供 API Key 时不得把替身结果写为真实模型通过。
