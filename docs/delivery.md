# 实施阶段与验收

本文件是验收计划；任何项目均需附可复现证据后才标记 PASS。

## 阶段

1. 固定 OpenSpec、数据库模型、API 契约和最小双端页面，完成登录与班级权限。
2. 完成材料上传、索引、混合检索、来源快照，以及 Agent/Skill/MCP 主路径。
3. 完成知识缺口归并、教师审核、补充索引和重问对照。
4. 完成同纲不同卷、作答冻结、异步批改及教师复核。
5. 完成学情周报、教师发布、失败恢复、全链路测试和部署。
6. 在干净 Linux 主机完成容器化冷启动，以虚构种子数据演示全流程，运行安全自动化测试和分级并发压测，归档原始结果。

## 必须演示的场景

| 场景 | 通过条件 |
| --- | --- |
| A/B 班隔离 | 跨班材料、会话、作业和 MCP 资源访问被服务端拒绝 |
| 无证据问答 | 说明证据不足并创建候选缺口，不伪造引用 |
| 教师回补 | 审核、补充、索引完成后，原问题重问命中新材料并显示出处 |
| 讲义版本 | 索引失败沿用旧版；成功后切换；历史引用不漂移 |
| 同纲不同卷 | 同班两名学生获不同实例；交换答案不能直接拿满分 |
| 任务隔离 | 一名学生发卷失败不影响其他学生；失败记录可见并可重试 |
| 批改复核 | AI 原分、教师最终分、复核依据分别保存 |
| 周报可信性 | 数字来自程序统计；样本不足不推断趋势；草稿不对学生开放 |
| MCP 调用 | 模型工具调用 ID 与执行结果关联；非法工具、越权或异常可审计 |
| 部署 | 容器健康、数据持久化、备份可恢复，公网 HTTPS 经实际验证 |
| Linux 冷启动 | 全新 Linux 主机仅依赖 Docker/Compose 和示例配置即可构建、迁移、初始化并访问 `/health` |
| 安全自动化 | 测试脚本只连接隔离测试环境；未登录、跨班、JWT、上传、下载、检索和 MCP 越权检查全部通过 |
| 并发性能 | 按 20/50/100/200 并发逐级实测，报告吞吐、p95/p99、错误率、CPU/内存及模型限流；达到约定容量门槛 |
| 种子数据 | 幂等初始化虚构 A/B 班、教师/学生、材料、问答、作业与评分，重跑不重复且可清理 |

## 证据要求

每项场景记录执行环境、测试输入、预期结果、实际结果和 PASS/FAIL/NOT RUN；保存必要的脱敏截图、接口响应及测试日志。CI 运行不替代公网部署验收。性能数字须标明基线、样本范围和实际计量方式。

当前仓库仅含规约，以上四项运行性门槛均为 **NOT RUN**；不得因为文档存在就标记 PASS。具体执行约束与门槛见 [Linux 部署与四项验收门槛](operations-acceptance.md)。
