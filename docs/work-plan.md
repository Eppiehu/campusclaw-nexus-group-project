# 开发任务拆解与完成定义

这是供两名成员讨论的实施计划，**不是已完成贡献记录**。具体负责人和截止时间以 Issue/PR 为准；`hxflb` 接受仓库邀请后共同确认。

## 1. 依赖顺序

1. 确认课程要求、产品范围、OpenSpec 能力场景、接口契约和环境变量。
2. 建立数据库迁移、认证与班级隔离，再做材料上传/正文/下载。
3. 建立检索、版本引用、应用配置与基础 Agent 会话，再接 Skill/MCP。
4. 增加知识缺口、同纲不同卷、批改复核和周报。
5. 以虚构种子数据做跨模块集成，补安全脚本、Linux 容器部署与并发压测。

## 2. 工作包

| 工作包 | 后端/基础设施交付 | 前端交付 | 完成定义 |
| --- | --- | --- | --- |
| WP1 身份与班级 | JWT 生命周期、成员关系、服务端 RBAC、审计 | 登录、身份恢复、角色导航 | 未登录/跨班/本人资源测试通过 |
| WP2 讲义知识库 | 上传校验、正文、版本、索引、RRF、引用 | 列表、正文、搜索、上传与状态 | TXT/MD/文字型 PDF、失败回退、下载权限可演示 |
| WP3 Agent/Skill/MCP | LangGraph、SSE、模板、Skill 白名单、MCP 二次鉴权 | 应用配置、会话、引用与工具状态 | 至少多个应用、一个可执行 Skill 与一个 MCP 工具真实验证 |
| WP4 知识缺口 | 候选、班级归并、审核、异步回补 | 教师审核与前后对照 | 无证据拒答、回补后命中、索引失败保持旧版 |
| WP5 作业与批改 | 模板、独立实例、答案快照、异步批改、复核 | 学生作答、教师模板与评分页 | 同纲不同卷、交换答案、单人失败、原分/最终分可追溯 |
| WP6 周报 | 事实聚合、样本门槛、草稿/发布 | 图表、编辑、审核与学生只读页 | 数字可追溯、样本不足说明、草稿不可见 |
| WP7 交付保障 | Docker/Compose、迁移、虚构种子、安全脚本、压测 | Playwright E2E 与界面回归 | 干净 Linux 冷启动、完整测试与容量报告 |

## 3. 两人协作建议

- 一人主导后端与 Agent/RAG/MCP/部署的集成骨架，另一人主导前端、作业/周报交互与端到端验收；模块归属不代表单人独做。
- WP1、WP2 的 API 契约和数据库设计由双方共同评审；每个工作包至少有另一位成员的 PR 审阅记录。
- 交叉验收：前端负责人验证真实 API 与权限，后端负责人验证 UI 可用性及错误反馈，双方共同在 Linux 复现部署。
- 原个人仓库的代码若被复用，须在 Issue/PR 标明来源、授权、改动与测试，不把旧提交算作本组共同开发。

## 4. 每项工作的完成定义

需求场景和接口已确认；实现与迁移可复现；自动化测试含正常、未登录、跨班与失败路径；文档和配置模板更新；PR 填写安全影响与 PASS/FAIL/NOT RUN；另一位成员审阅；合并后在干净环境验证。未满足任何一项时保留未完成状态。
