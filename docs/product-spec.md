# 产品规范（规划版）

本规范定义小组项目的产品目标和验收边界，当前不是已完成功能清单。任何功能开发应先关联需求、设计与测试记录。

## 1. 产品定位与用户

CampusClaw Nexus 面向同一课程中的教师和学生。教师管理本班讲义、教学 Agent、作业与学情；学生阅读本班材料、提问、提交本人作业并查看允许公开的反馈。系统以班级作为主要资源隔离边界。

## 2. 产品原则

1. **有据可查**：知识库回答附材料标题、版本和片段；证据不足时说明不足并形成候选知识缺口。
2. **权限可靠**：服务端根据已认证身份确定角色和班级，所有列表、详情、下载、检索与工具调用逐项校验。
3. **人机分工**：AI 提供建议，标准答案、成绩最终值、讲义发布和周报发布由确定性规则或教师确认。
4. **状态可见**：索引、发卷、批改、报告生成等异步操作显示排队、运行、成功和失败；失败可以诊断和重试。
5. **历史可追溯**：讲义版本、问答引用、批改依据和教师复核记录不可被后续编辑悄悄改写。

## 3. 页面与核心流程

### 登录与工作台

- 登录后展示本人身份与当前班级；教师和学生进入相应工作台。
- 退出后令牌失效。未登录访问受保护资源返回明确的未认证结果；越权返回拒绝访问。

### 讲义知识库

- 教师选择班级，填写标题，上传 TXT、Markdown 或文字型 PDF；页面展示解析与索引状态。
- 教师可查看正文、版本、来源和生效状态；上传新版本时旧版本继续服务，直到新索引成功并切换。
- 学生只能浏览、搜索、查看和下载本班生效材料。搜索结果展示标题、命中片段与版本。
- 对扫描型 PDF、空文件、超限文件和解析失败给出可理解的错误，不标记为已索引。

### 教学 Agent 与对话

- 教师创建多个 AI 应用，配置提示词模板、知识库范围、可用 Skill 与 MCP 工具，并进行测试与启停。
- 学生从本班可用应用进入多轮会话；回答可流式展示，引用可点开原材料片段。
- 工具调用显示执行中的状态；失败时给出反馈，不展示虚构的工具结果。
- 无足够证据时拒绝编造结论，并将问题登记为本班候选知识缺口。

### 知识缺口回补

- 教师在本班查看候选缺口、相似问题、热度和相关会话证据。
- 教师确认或驳回；确认后上传补充材料并启动索引。
- 索引完成后可用原问题重问，与回补前结果并排比较；索引失败保持原状态和错误记录。

### 同纲不同卷与批改

- 教师维护题目模板、参数范围、Rubric、开放时间和班级范围。
- 系统为每名学生生成并冻结独立题目实例与服务端答案；学生只查看本人题目和提交状态。
- 批改结果区分 AI 建议分、教师最终分、评分依据和复核时间。重新批改不覆盖历史记录。
- 单个学生实例生成失败应单独记录，不影响其他学生作答。

### 学情周报

- 教师选择班级和周期，程序先聚合提交、评分、检索与知识缺口事实。
- AI 根据聚合结果生成文字草稿；页面展示数据来源、样本量和模型生成标记。
- 教师可编辑、审核和发布。未发布的周报不对学生开放；样本不足时不推断趋势。

## 4. 最小交付范围

第一轮可用版本必须跑通登录、A/B 班隔离、讲义上传与检索、带出处的问答、一个可执行 Skill、一个 MCP 工具、独立作业实例、AI 初评与教师复核。三项新增业务的完整验收依照 [实施阶段与验收](delivery.md) 执行。

## 5. 可用性与异常规则

- 操作按钮在提交中防重复；成功后可回到对应资源并看到最新状态。
- 表单错误指出具体字段；异步失败保留任务编号、时间和可阅读原因。
- 对话记录和引用支持按会话查看；页面不显示令牌、密钥或敏感日志。
- 教师执行撤回或发布时展示影响范围；历史引用仍指向旧快照。

## 6. 验收口径

真实 API、数据库和模型/工具链路的实测结果才可标为 PASS。仅有页面截图、mock 响应或设计文档时标为 NOT RUN。每个功能至少覆盖正常、未登录、跨班和失败路径。
