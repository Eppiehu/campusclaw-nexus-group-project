# 安全规范（规划版）

本规范适用于设计、开发、测试与部署全过程。它是验收要求，不表示当前系统已满足。

## 1. 身份与授权

- API 使用有有效期的 JWT Bearer；验证签名、算法、签发方、受众和过期时间。退出登录或禁用账号后可撤销令牌。
- 服务端依据令牌对应的当前用户、角色和班级成员关系确定权限，不信任客户端传来的 `role`、`class_id` 或资源所有者字段。
- 教师仅能管理任教班级；学生仅能访问本班公开材料和本人作业、提交、成绩、错题及会话。
- 对列表、详情、下载、搜索、引用跳转、导出、异步任务和 MCP 工具逐项检查；未认证返回 401，越权返回 403 或按统一防枚举策略处理。
- 权限变更后应及时生效；高权限操作记录操作者、对象、班级、时间和结果。

## 2. 班级隔离与数据保护

- 数据库查询与向量/全文检索在查询阶段限定授权班级，不先取全量结果再在前端过滤。
- 检索片段、模型上下文、工具参数和返回值仅包含当前授权请求所需内容；跨班片段不能进入模型请求。
- 历史引用绑定不可变材料版本；撤回材料后普通用户不可继续访问被撤回正文，审计与历史记录按保留策略处理。
- 测试与演示使用虚构资料；真实学生数据的收集、外发和保留需另行确定合法依据和最小范围。

## 3. 上传、下载与输入

- 只接受约定格式和大小的文件；验证真实内容类型、扩展名、编码及解析结果，拒绝路径穿越、空文件和恶意超限内容。
- 上传文件使用随机存储名，保留原名仅作显示；下载按资源 ID 重新鉴权，不拼接客户端提供的磁盘路径。
- Markdown、PDF 文本和模型输出作为不可信内容处理；页面渲染需防脚本注入，文件解析运行在受限环境。
- 所有写操作验证字段、长度和参数范围；数据库查询使用参数化语句。

## 4. AI、Skill 与 MCP

- 讲义和网页内容可能包含提示注入。检索文本只能作为证据，不能改变系统规则、扩大权限或触发未授权工具。
- 模型只能调用已绑定且当前用户获准使用的工具；每次执行再次验证工具名、参数、角色、班级和资源归属。
- Skill 上传需约定格式、大小、审核与启用流程；禁止直接执行未经审核的任意脚本。运行时限定超时、资源与可访问工具。
- 工具调用与结果按 `tool_call_id` 关联，记录脱敏参数摘要、授权决定、耗时和错误；异常不得泄露堆栈、密钥或其他班级数据。
- 对外部模型发送最小必要的提示词、当前对话与检索证据；密钥仅存服务器配置，不进入前端、仓库或日志。

## 5. 凭据、部署与审计

- Git 仓库不得包含密码、Token、API Key、SSH 私钥、真实数据库备份或 `.env` 实值；提交前检查敏感信息。
- 使用环境变量或受控密钥存储；为开发、测试和生产分配不同凭据，泄露后立即轮换。
- 最终公网服务使用 HTTPS；数据库、Redis 和 Worker 不直接暴露公网。容器采用最小权限和持久化备份。
- 日志记录请求标识、操作者、班级、操作、授权结果和任务状态；对个人信息、令牌和模型输入做脱敏与访问控制。
- 出现越权、凭据泄露或异常数据外发时，先隔离影响、保留必要证据，再轮换凭据和修复，记录复盘。

## 6. 安全验收

至少验证未登录访问、学生上传、跨班列表/详情/下载/检索/MCP、篡改班级参数、文件类型伪装、路径穿越、提示注入、失效令牌与敏感日志泄露。每项记录实际结果及 PASS/FAIL/NOT RUN；未执行的测试不得标为通过。
