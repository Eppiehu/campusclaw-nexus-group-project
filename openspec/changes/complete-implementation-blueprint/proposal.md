# 变更：补齐可开工的实施级规范

## 背景

小组仓库已有产品目标、安全边界与验收场景，但开发者还需要明确前后端分工、具体页面和接口、数据关系、容器拓扑与环境变量。老师后续会在 Linux 上验收，因此配置与部署步骤需要在写代码前形成一致的设计。

## 目标

- 明确前端页面、路由、状态管理与 SSE 交互；后端模块、请求链路、Worker 与 Agent/Skill/MCP 执行边界。
- 提供拟定 API 清单、逻辑数据模型、无密钥配置模板、环境变量说明与 Linux 部署方案。
- 将工作拆解为可由两人通过 Issue/PR 认领和交叉验收的工作包。
- 让 AI 开发助手能从 `AGENTS.md` 找到必须先读的规范与验证路径。

## 范围

本次只提交 Markdown 规范与 `.env.example` 无密钥配置模板。**不提交前后端代码、Dockerfile、Compose、迁移、测试脚本、真实账号或密钥。**

## 验收

1. README 能导航到所有实施文件；文件间技术栈、端口、认证方式与环境变量不冲突。
2. 前端、后端、接口和数据模型各有明确责任、权限和失败路径。
3. `.env.example` 无真实凭据，配置文档解释每个变量及演示/生产差异。
4. Linux 部署方案与既有四项运行验收门槛对应，但没有把计划标成运行 PASS。
5. OpenSpec 严格校验通过；文档经另一位小组成员 PR 审阅后合并。
