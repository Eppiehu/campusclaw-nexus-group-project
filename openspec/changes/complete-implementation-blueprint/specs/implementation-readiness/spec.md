# Spec Delta

## Purpose

明确文档型仓库在引入代码前必须具备的前后端设计、接口与数据契约、无密钥配置及 Linux 部署蓝图，防止开发时凭口头约定产生不一致。

## ADDED Requirements

### Requirement: 前后端职责可执行
仓库 SHALL 描述教师/学生页面、前端状态与请求层，以及后端认证、材料、检索、Agent、作业、缺口、周报和异步任务的模块责任。

#### Scenario: 新成员认领工作包
- **WHEN** 小组成员准备实现一个功能
- **THEN** 能从文档找到页面、API、服务模块、数据实体、权限路径和完成定义

### Requirement: 契约与数据保持一致
仓库 SHALL 以拟定接口清单和逻辑数据模型说明请求方法、错误码、班级/所有者归属、版本与任务状态；实现变更 SHALL 先更新契约再写代码。

#### Scenario: 修改跨班资源接口
- **WHEN** 开发者准备新增或改变材料、作业、会话或 MCP 接口
- **THEN** 先更新权限与错误场景，再修改实现和测试

### Requirement: 配置模板不泄露秘密
仓库 SHALL 提供无真实凭据的环境变量模板，并说明必填项、默认策略、演示/生产差异和缺失模型密钥时的行为。

#### Scenario: 老师查看仓库配置
- **WHEN** 老师或评审者打开 `.env.example`
- **THEN** 能看见所需变量名和非秘密默认值，不能取得真实密码、Token 或 API Key

### Requirement: Linux 部署路径可核对
仓库 SHALL 描述容器服务、网络、卷、冷启动、迁移、种子数据、健康检查和失败回退，并把实际运行与计划状态分开。

#### Scenario: 只有规范、尚无代码
- **WHEN** 评审者检查当前仓库
- **THEN** 部署、自动化安全测试、并发和种子数据运行状态仍显示 NOT RUN，不会因文档完整而误标 PASS
