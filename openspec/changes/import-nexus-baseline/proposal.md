# 变更：有来源地导入 Nexus 实现基线

## 背景

小组仓库已建立产品、技术、安全和验收规约；维护者现要求将已有项目实现推入小组仓库，供两名成员后续开发。个人项目与小组目标并非完全相同，导入不能冒充共同开发或最终验收。

## 范围

选择性导入个人仓库提交 `a770f6a` 的 Nexus 后端、前端、迁移、虚构种子、测试和容器文件；排除课程旧版、真实环境文件、运行数据、大型二进制及个人作业报告。建立独立 Flask 入口，改造容器构建对本地 `dist` 与模型缓存的依赖，明确差异和后续工作包。

## 验收

- 仓库只包含可审查的源码、锁文件、规约和无密钥模板；来源可追溯。
- 语法/前端构建、CI、容器冷启动和外部集成逐项给出 PASS/FAIL/NOT RUN，不继承个人项目的历史结论。
- 班级隔离、工具二次鉴权、种子数据和权限测试保留；未达到小组目标的条目明确列入差异表。
- 通过独立分支和 PR 交由另一名组员审查，不绕过主分支保护。
