# Design

## Context

小组作业需要一个与个人代码仓库分开的开发基线。当前仓库仅有文档，尚无可运行系统。教师将来会在独立 Linux 环境验证部署；因此技术选型、权限边界、可复现数据和运行门槛必须在开发前写清楚。

## Goals / Non-Goals

**Goals:**

- 将教师/学生、班级、讲义、Agent、作业与三项新增业务转成可测试的需求。
- 固定产品、架构、安全、接口和运行验收之间的追溯关系。
- 让两名成员能在同一仓库通过 Issue/PR 共同评审与交付。

**Non-Goals:**

- 此变更不实现 API、页面、容器、测试脚本或种子数据。
- 不迁移个人仓库代码，也不宣称任何性能或部署结果已通过。

## Decisions

### 1. 规划与运行结果分离

需求使用 OpenSpec `SHALL` 和 `WHEN/THEN` 场景；运行状态独立记录为 PASS、FAIL、NOT RUN。理由是老师的 Linux 验收依赖可运行证据，规范文本本身不能替代。替代方案是只写愿景式 README，但难以核对异常路径。

### 2. 班级范围由服务端确定

所有业务实体保留班级/所有者归属。认证后从服务端当前成员关系取得有效班级；列表、详情、下载、检索和 MCP 工具分别鉴权。理由是前端过滤无法阻止修改请求参数。跨班数据不得进入模型上下文。

### 3. 检索证据与生成结果分离

PostgreSQL/pgvector 的全文与向量检索按授权范围执行，RRF 合并后只将必要片段传给模型。引用记录材料版本和片段快照；无证据时拒绝编造并登记候选缺口。理由是既要可溯源，也要避免全库外发。

### 4. 高风险教学结果采用人机复核

题目标准答案保留服务端，AI 批改为建议；教师最终分与原分分开保存。周报数字由程序聚合，AI 只解释，发布由教师确认。理由是模型输出不适合作为不可复核的事实来源。

### 5. 异步任务与版本切换

索引、发卷、批改和周报任务先持久化再入队，保留失败与重试；材料索引成功后才原子切换活动版本。理由是队列失败或更新中断不能让旧资料失效或历史引用漂移。

### 6. Linux 环境是最终验收基准

采用 Docker Compose 组织前端、API、Worker、PostgreSQL 和 Redis；镜像可复现构建，种子数据幂等，安全脚本默认只在隔离环境运行。普通 API 与外部模型/SSE 分开压测，记录机器规格和原始结果。

## Risks / Trade-offs

- pgvector、Redis/RQ、LangGraph 与 MCP 增加部署复杂度；需要健康检查、版本固定和故障演练。
- DeepSeek 延迟和限流不完全受系统控制；并发报告需分清本机瓶颈与供应商限制。
- 公开仓库不能保存演示密码或真实学生数据；老师部署时须从环境变量设置演示凭据。
- 两人协作邀请只有接受后才形成共同写入权限；在 GitHub 状态确认前不能宣称已完成共享。
