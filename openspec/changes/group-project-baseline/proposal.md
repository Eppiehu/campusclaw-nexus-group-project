# 变更：建立 CampusClaw Nexus 小组项目基线

## 背景

课程个人项目已有 CampusClaw 相关实践；开发小组作业需要独立的需求、设计、开发和验收记录。本变更先建立文档基线，后续实现必须由小组成员通过 Issue 与 PR 逐项交付。

## 目标

- 明确教师与学生的班级隔离、讲义知识库、Agent/Skill/MCP、作业与批改主路径。
- 定义知识缺口回补、同纲不同卷、多源学情周报三项新增业务。
- 固定拟采用的框架、数据边界、异常状态、部署目标和验收证据要求。
- 建立两位成员共同维护的 OpenSpec、评审和贡献记录流程。
- 将 Linux 容器冷启动、安全自动化测试、并发容量验证和虚构种子数据列为最终交付门槛。

## 范围

本次仅提交产品规范、功能要求、架构、接口/数据契约、验收、协作规则，以及可测试的 OpenSpec 能力规约。**不提交应用源代码，不声明系统已交付。**

## 非目标

- 不迁移个人仓库代码或历史提交。
- 不发布服务，不提交生产数据或凭据。
- 不把计划中的性能、HTTPS、模型效果或贡献比例写成已验证结果。

## 验收

1. 仓库中只有文档和 OpenSpec 规约，没有前后端源代码、依赖文件或部署密钥。
2. 产品规范覆盖教师与学生的核心任务、页面、异常和权限边界。
3. 三项新增业务均有状态流转、失败路径和可复现的验收场景。
4. 技术选型与业务要求分开描述，计划与已完成状态清楚区分。
5. 两名成员都能访问仓库，并通过 Issue/PR 留下可核对的贡献与评审记录。
6. 四项运行性门槛有明确执行环境、测试边界、通过条件和证据要求；未实现前统一标为 NOT RUN。
