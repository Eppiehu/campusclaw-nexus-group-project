# Spec Delta

## Purpose

定义讲义检索、来源追溯、Agent/Skill/MCP 调用及知识缺口回补的行为，保证回答基于授权证据且工具执行可审计。

## ADDED Requirements

### Requirement: 授权范围内的知识检索
系统 SHALL 只对当前用户有权访问的生效材料进行全文与向量检索，并在回答中绑定材料版本和片段出处。

#### Scenario: 命中有效证据
- **WHEN** 学生提问命中本班讲义
- **THEN** 回答包含可打开的材料标题、版本和片段引用，模型只接收本次必要片段

#### Scenario: 无充分证据
- **WHEN** 授权材料中没有足以支持回答的证据
- **THEN** 系统说明证据不足，不编造引用，并登记本班候选知识缺口

### Requirement: 安全的材料版本切换
系统 SHALL 保留不可变材料版本，在新索引成功后切换活动版本，并保持历史引用指向原快照。

#### Scenario: 新版本索引失败
- **WHEN** 教师上传新版本但解析或索引失败
- **THEN** 旧版本继续可检索，失败原因可见，历史引用保持不变

### Requirement: 可控的 Agent 与工具调用
系统 SHALL 支持多个 AI 应用、提示词模板、可启停 Skill、MCP 工具和多轮 SSE 会话；工具执行前 SHALL 二次鉴权。

#### Scenario: 允许的工具执行
- **WHEN** 模型请求调用已绑定且当前用户获准使用的工具
- **THEN** 系统记录 `tool_call_id`、脱敏参数、执行结果或错误，并将结果关联回该次会话

#### Scenario: 未授权工具或提示注入
- **WHEN** 材料文本试图指示模型调用未绑定工具或读取其他班级数据
- **THEN** 系统拒绝该操作，保留审计记录，不把材料内容当成权限指令

### Requirement: 知识缺口回补
系统 SHALL 允许教师审核本班候选缺口，补充材料并比较回补前后的检索结果。

#### Scenario: 教师审核并回补
- **WHEN** 教师确认缺口、补充材料且新索引完成
- **THEN** 缺口标为已补入，原问题重问可显示新材料出处及前后对照
